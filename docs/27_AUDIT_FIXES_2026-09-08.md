# September 8 audit fixes

These changes address the engineering findings in [the initial audit](26_PROJECT_AUDIT_2026-09-08.md). Accepted for production release on September 8, 2026. The existing Supabase database was baselined through 0014 without replaying SQL, then migration 0015 was applied successfully. The ledger reports 15 versions and no pending migrations. This release is published through GitHub main and the existing Vercel integration; consult the deployment/check status for the current rollout result. No payment or hosting-plan purchase was made.

## Generation and payment

- Production generation requires an authenticated account and service-role database access, even when coin charging is disabled. Local development without Supabase is supported only with coins disabled; its records are process-local.
- `generation_matches` stores the canonical session, generated answers, fixed match/judge quotes, and resolved Auto judge. Every request is scoped to the authenticated owner. The server rebuilds prompts from its own transcript and round plan; client messages, roles, tasks, provider names and completion flags do not authorize work.
- Only English Debate Mode, three short rounds and Auto/selected judging can start new generation. Deep Debate keeps its three-round, serious-tone policy and longer output. Legacy sessions remain viewable; sessions created before server persistence must start a new match to generate or rejudge.
- One database lease allows generation per match at a time. Each lease has a unique token and a 120-second expiry, longer than the route's 60-second limit. Completion requires the current token. Completed responses are returned from storage on replay; different judges have separate cached responses.
- A turn or judge can claim at most three attempts that reach paid work. Provider retries within an attempt are also budgeted. Rejections before a spend reservation do not consume this allowance. Unknown outcomes retain their reservations, and an abandoned lease can be reclaimed after expiry.
- The included Auto judge requires six completed server-owned turns and the original match charge. Third-model charges use the stored quote. Pricing updates cannot change the amount of an existing match's charge.

## Spending and prices

`spend_reserve` atomically books global and per-IP allowance before each model attempt or search. All workers share a UTC-day database lock. `spend_settle` reconciles known usage once, against the original booking day. Failed, aborted, missing-usage or ambiguous calls retain the conservative reservation; an accounting outage blocks new paid work in production.

Model reservations use UTF-8 prompt bytes plus message overhead, the actual completion ceiling including reasoning, and the higher input/cache-write rate. Known OpenRouter costs use the returned cost receipt; other usage uses the maintained tariff table. Native OpenRouter search is disabled because its additional input and fees cannot be bounded by the normal completion budget. All Deep Debate searches use the app-managed Brave path, with a default/minimum $0.005 booking per query. Disabled speech also has a conservative per-request booking if later enabled.

These are conservative application budgets, not guarantees about a provider invoice or arbitrary future tariffs. A provider can report a cost above its reservation; reconciliation records it and blocks subsequent work as appropriate. Message summaries describe successful answers, while the spend ledger also includes failed attempts.

Coin pricing now uses the least valuable pack after a documented 10% plus $0.30 processing allowance, a 20% retry allowance, a 10% operating allowance, hidden reasoning, longer/deep output, searches, and the included judge. The target is 5× estimated cost, not guaranteed profit. Pack offers remain unchanged. The match adds a 4-coin Auto judge allocation; Deep Debate adds 20 purchased/promo coins. See [the coin specification](23_COINS.md) and `economy.ts` for current per-model bands and assumptions.

## Data and privacy

Server generation records are separate from saved profile history. Deleting a history item does not remove the generation record and allow replay of a previously paid session. Account deletion cascades to generation records. Account export includes the caller's own generation records through a restricted RPC; raw generation tables remain unavailable for client writes. Privacy copy explains these distinctions. IP spend records contain accounting metadata rather than debate text.

## Release procedure

Use the same deployment's server-only Supabase configuration. The runner uses an advisory lock, a version/checksum ledger, and a transaction for each migration plus its ledger entry. It refuses a populated database with no baseline. Baseline records reviewed historical versions without replaying their SQL.

```sh
# Read-only inspection of the existing database:
node scripts/apply-migrations.mjs --status
node scripts/apply-migrations.mjs --baseline-through 0014 --dry-run

# On the verified existing database, once per installation:
node scripts/apply-migrations.mjs --baseline-through 0014

# Review, then apply only pending changes:
node scripts/apply-migrations.mjs --dry-run
node scripts/apply-migrations.mjs
node scripts/apply-migrations.mjs --status

npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

Apply migration 0015 before releasing the application that calls it. A new empty database uses the normal runner without a baseline. Do not edit previously applied SQL; add another migration. An old application rollback cannot preserve the new generation protections, even though the additive schema remains compatible.
